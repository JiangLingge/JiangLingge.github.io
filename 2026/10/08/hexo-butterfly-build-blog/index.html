在别人的平台上写过一些东西，总觉得不太自在：排版是别人的，广告是别人的，数据也是别人的。所以干脆自己搭一个。

这篇把我搭建时踩过的坑按顺序记一遍，环境是 Windows + Node.js + Hexo 8 + Butterfly 5，全程照着敲就能跑起来。

一、环境准备

真正需要装的只有两样东西：Node.js 和 Git。

二、安装 Hexo

目录建好后是长这样的：

文件 / 目录 作用
_config.yml 站点主配置：标题、作者、网址、分页
source/_posts/ 放文章的 Markdown 文件
themes/ 主题目录
public/ 生成的静态网页，部署时上传的就是它
package.json 依赖清单和快捷命令

hexo init 会自动装一个默认主题，先启动看看：

浏览器打开 http://localhost:4000 就能看到默认站点。4000 端口被占用的话可以指定别的端口：hexo s -p 5000。

连不上时先看看是不是防火墙或安全组没放行端口，这一步很容易忘。

五、建齐页面

顶部的归档、标签、分类、友链是独立页面，需要手动创建，否则点进去是 404。

创建后分别编辑生成的 source/<名字>/index.md，关键是 type 字段：

页面 type 写法
标签 type: tags
分类 type: categories
友链 type: link
关于 不写 type，当普通页面写内容即可

归档页不需要自己建，Hexo 会自动生成 /archives/。

友链页的内容从哪来

Vercel / Netlify

把站点推到 GitHub 仓库，导入平台后设置：构建命令 npx hexo generate，输出目录 public。好处是每次 push 自动重新构建。

自己的服务器

hexo g 之后把整个 public/ 目录拷到服务器，用 Nginx 指过去就行。纯静态站点，服务器上不需要装 Node.js。

八、踩坑记录

现象 原因
配置改了没生效 冒号后面漏了空格，或者用了 Tab 缩进
主题样式全乱 没装 hexo-renderer-pug / hexo-renderer-stylus
npm install 卡住 没换国内镜像
点菜单 404 对应页面还没 hexo new page
图标不显示 CDN 被墙，把 CDN.third_party_provider 改成 local 并装 hexo-butterfly-extjs
升级主题后配置丢了 改的是 themes/butterfly/_config.yml，应该改根目录外置的那份
