三、什么时候该 hexo clean

hexo clean 会删掉 public/ 和 db.json 缓存。下面这些情况先 clean 再说，能省掉大量莫名其妙的调试：

  • 改了主题配置但页面没变化
  • 删了文章但归档里还在
  • 改了 permalink 后出现了重复目录
  • 文章里图片路径改了但显示的还是旧图
  • 样式错乱、布局诡异

hexo server 会边改边热更新，但配置文件（_config.yml / _config.butterfly.yml）的改动不会热更新，改完必须重启 server。这一点经常被忽略，然后对着屏幕怀疑人生。

四、常见故障速查

现象 原因与处理
启动报 YAMLException 配置里冒号后没空格，或用了 Tab 缩进
配置改了不生效 改的是 themes/butterfly/_config.yml，应该改根目录那份
页面没有样式 缺 hexo-renderer-pug、hexo-renderer-stylus
图标全是方块、搜索失效 CDN 被墙，把 CDN.third_party_provider 改 local 并装 hexo-butterfly-extjs
hexo s 报端口占用 hexo s -p 5000 换端口，或杀掉占用 4000 的进程
新文章不显示 front-matter 的日期是未来时间，或文章被标了 draft
文章「最后更新」时间不对 本站 updated_option: 'mtime'，取的是文件修改时间，用 touch 改一下或在 front-matter 里写死 updated
时区显示差 8 小时 _config.yml 里 timezone: 'Asia/Shanghai'
部署完域名打不开但 GitHub 地址能开 CNAME 文件被覆盖了，确认它在 source/CNAME
hexo d 报认证失败 用了登录密码，应该用 Personal Access Token
